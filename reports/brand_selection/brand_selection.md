## Methodology Notes

1. **Resolution heuristic** is approximate: we check if the brand's final message
   in a thread contains keywords like "dm", "resolved", "sorry", "help center".
   This under-counts silent resolutions and over-counts apologies that don't fix
   the problem. Weight deliberately kept low (0.10) to limit this distortion.

2. **Thread reconstruction** in this script uses a fast parent-chain traversal
   rather than the full BFS used in the data pipeline — sufficient for relative
   ranking, not for generating the actual training data.

3. **Topic diversity** uses unigram vocabulary size on a sub-sample of customer
   messages. This is a cheap proxy; a proper k-means cluster count would be more
   precise but adds ~10× runtime for marginal improvement at the ranking stage.

4. **Sample size**: 200,000 rows covers ~7% of the dataset.
   Metric estimates are stable at this scale (standard error on proportions < 0.3%).
